## Problem Statement

Cleaning up motion capture (mocap) data is a tedious, labor-intensive bottleneck in media and entertainment (M&E) pipelines. Animators spend hours manually fixing jitter, foot sliding, and joint limit violations using 3D Digital Content Creation (DCC) tools. Furthermore, communicating complex spatial fixes (e.g., director's notes) requires extensive back-and-forth.

## Solution

A production-ready, dynamic multi-agent system powered by the Google Cloud Agent Development Kit (ADK) and Gemini 1.5 Pro. The system features a React web dashboard that allows animators to upload BVH files and record multimodal audio (spoken notes). A Supervisor agent routes the task to specialized worker agents (Kinematics, Contact), which query a ClickHouse Vector DB (RAG) for historical fixes to generate high-quality `bpy` (Blender Python) correction scripts. The animator can tweak these scripts in a White-Box code editor before headless execution, saving LLM tokens and ensuring human-in-the-loop control. The architecture supports batch processing via Google Cloud Run to prove enterprise scale.

## User Stories

1. As an animator, I want to upload a `.bvh` file to a web dashboard so that I can begin the cleanup process without installing complex backend dependencies.
2. As a director or animator, I want to record and submit a multimodal audio note (e.g., "pin the left foot") so that I don't have to type out complex spatial descriptions.
3. As a technical director (TD), I want to see the Python (`bpy`) script generated by the agent before it runs so that I can verify its safety and logic.
4. As a TD, I want to manually edit parameters in the generated `bpy` script and re-run it locally so that I can fine-tune the animation without burning the $300 Gemini API token budget on a retry prompt.
5. As an enterprise studio manager, I want to upload a batch of up to 5 `.bvh` files so that they are processed asynchronously and concurrently via Cloud Run Jobs, saving animator time.
6. As a developer, I want the Supervisor Agent to dynamically spin up specialized agents (Kinematics Expert, Contact Expert, QA Judge) so that complex mocap problems are handled by focused context windows.
7. As an agentic system, I want to query a ClickHouse Vector Database using MCP so that I can retrieve and apply historically successful script parameters to current anomalies instead of hallucinating from scratch.
8. As a QA Judge agent, I want to evaluate the output of the worker agents against hard kinematic constraints so that I can guarantee the final animation obeys physical laws before presenting it to the human.
9. As a hackathon judge, I want to test the solution immediately via a public URL so that I don't have to install Blender or configure local environments.

## Implementation Decisions

- **Architecture:** React SPA frontend hosted on Firebase Hosting; FastAPI backend orchestrating Google Cloud ADK and headless Blender, containerized on Google Cloud Run.
- **Agent Orchestration:** Dynamic multi-agent studio (Supervisor -> Workers -> QA Judge) built natively using `google-cloud-aiplatform[agent_engines,adk]`.
- **RAG & Partner Track:** ClickHouse deployed as a Vector DB. Agents will use ClickHouse MCP to query historical fixes (embeddings of semantic descriptions and kinematic signatures).
- **Multimodal Audio:** Web `MediaRecorder` API captures audio, sending it to the FastAPI backend, which passes the raw audio blob directly to Gemini 1.5 Pro to preserve tone and inflection.
- **Budget Control (White-Box):** The React frontend features a code editor component. The backend pauses execution, sends the generated `bpy` code to the frontend, and waits for a "Run" signal (with optional code edits) from the human-in-the-loop.
- **Batch Processing:** Uses Google Cloud Run Jobs for concurrent headless Blender execution, artificially capped at 5 parallel files to protect API budgets.

## Testing Decisions

- A good test validates the external behavior (e.g., a file uploaded with a specific audio command yields a modified BVH output) without mocking the internal ADK steps unless necessary for cost.
- **Seams for Testing:**
  1. **Frontend-Backend API Seam:** The highest level seam. We will test the FastAPI endpoints directly by posting sample `.bvh` data and audio blobs, ensuring the job queue processes them and returns a valid script/BVH.
  2. **ADK Agent Orchestration Seam:** We will test the agent routing logic by mocking the LLM responses to ensure the Supervisor correctly routes a "foot sliding" prompt to the Contact Expert Agent.
  3. **ClickHouse MCP Seam:** Test the retrieval pipeline by querying the vector DB with a mock anomaly description and asserting it returns the expected historical `bpy` parameters.
- Prior art: We will use `pytest` for backend API and unit testing, and standard React testing library for the white-box editor component.

## Out of Scope

- Native Blender/Maya DCC plugin integration (omitted in favor of a universally accessible web dashboard for hackathon judging).
- Processing batches larger than 5 files (artificially capped to protect the $300 budget).
- A fully automated loop without human approval (human-in-the-loop is required for the white-box code editor).
